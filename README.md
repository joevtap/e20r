# e20r — effect-adoption-analyzer

A CLI that measures how the [Effect](https://effect.website) library is
adopted in open-source TypeScript. It crawls the top TypeScript repositories
on GitHub by stars, decides which ones adopt Effect, and analyzes how
deeply they use it, down to per-file imports and symbol usages. Everything
is recorded in one SQLite database that you can query directly or browse
in the bundled viewer.

## Quick start

Requirements: Node 24 (pnpm downloads it through `devEngines` if needed),
pnpm, git, and a GitHub token (any fine-grained token works: search needs
no permissions, the token only raises the rate limit).

```sh
pnpm install
cp .env.example .env      # set GITHUB_API_KEY; this example selects budget 1200
pnpm build
pnpm e20r run --concurrency 2   # crawl, then process; measure capacity first
pnpm e20r view            # browse the results: http://127.0.0.1:4173/
```

Read the [operating guide](docs/operations.md) before a long or agent-run
job. It covers capacity checks, disk-backed isolated caches, process limits,
monitoring, timed interruption and resume. The code defaults to budget
5,000 and concurrency 4; the example configuration selects budget 1,200.
Concurrency 2 is a cautious starting point, subject to fresh measurements.

For a long run, start it in something that outlives your terminal, using
the cache and concurrency chosen in that guide:

```sh
mkdir -p "$HOME/e20r-runs/logs"
tmux new -s e20r 'pnpm e20r run --concurrency 2 --cache-path "$HOME/e20r-runs/cache" >>"$HOME/e20r-runs/logs/run.log" 2>&1'
```

Interrupt with Ctrl-C or SIGINT and allow cleanup to finish. Committed
crawl pages and repository transactions are the resume source; unfinished
work is repeated. A crash or forced kill can leave work directories and an
unfinished run record. Resume with the same persistent cache after checking
shutdown; see the [stop/resume procedure](docs/operations.md#after-stop-verify-and-resume).

## How it works

1. **Crawl.** GitHub search for `language:typescript fork:false
   archived:false`, sorted by stars. Search caps a query at 1,000 results,
   so the crawl walks star intervals (`stars:<=N`). It stops once it holds
   `REPO_SEARCH_BUDGET` repositories and has passed the star count at that
   rank, so ties at the cut-off are all included. Requests are paced
   evenly, one every 6 seconds: the documented search quota is 30 a minute,
   but GitHub's secondary limit refuses sorted repository searches at 15 a
   minute, and each refusal costs a one-minute wait. Each page is committed
   together with the cursor of the next one, so the crawl can be resumed,
   and a completed crawl is not repeated.
2. **Process** each of the top-N repositories, `CONCURRENCY` at a time, in
   its own throwaway work directory:
   - a **blobless shallow clone**: trees only, no file contents;
   - the **tree listing**: the file inventory, lockfiles and manifests,
     still without downloading any file;
   - a **selection checkout** of the `package.json` files and the root
     `pnpm-workspace.yaml` (catalog lookups). A repository is an
     **adopter** when some manifest declares `effect` in
     `dependencies` or `optionalDependencies` (a `catalog:` reference
     counts). Dev-only and peer-only usage is recorded but not counted;
   - **exclusion**: repositories owned by the Effect-TS org, listed in
     `EXCLUDE_REPOS`, or that define `effect` / `@effect/*` packages in
     their own tree (copies of Effect) are recorded as `excluded`;
   - an **analysis checkout** of the TypeScript sources (plus the
     selection files), for the remaining adopters, then the
     **deep analysis**. Every file is read once and measured (LOC), and
     every file whose text mentions `effect` at all is counted: parsed
     with [oxc](https://oxc.rs), or — above `MAX_PARSE_BYTES` — scanned
     as text for its imports only (no symbol counts). Imports and symbol
     usages are counted with aliases resolved
     (`Effect as E; E.gen()` counts as `Effect.gen`);
   - **one transaction** commits everything the repository contributes,
     then the work directory is deleted.

Hidden directories (`.repos/`, `.github/`, …), `node_modules`, `dist`,
`build`, `out`, `coverage` and `vendor` are skipped at every step. A
vendored copy of Effect therefore neither makes a repository an adopter
nor gets it excluded.

Every file gets a **role**:
- `generated`, from path conventions (`*.gen.ts`, `*.generated.ts`,
  `*_pb.ts`, `__generated__/`, `generated/`, …) or a generator header
  (`@generated`, "This file is auto-generated", "Code generated by …");
- `test`, for `*.test.ts`, `*.spec.ts`, `test/`, `__tests__/`, `e2e/` and
  the like;
- `source` for everything else.

Resource usage depends on repository size and adoption depth. Each analyzing
repository reads up to 8 whole source files concurrently, including files
above `MAX_PARSE_BYTES`, and retains per-file results until the repository
transaction completes. Git children, tree inventories, parser allocations,
SQLite and filesystem cache add overhead. Sparse checkouts also retain Git
objects and indexes; checkout size alone does not predict disk usage.
Measure the entire process tree and cache, including database journals and
logs. See the [resource model and tuning guidance](docs/operations.md#resource-model-and-tuning).

## Commands

| Command | What it does |
| --- | --- |
| `e20r run` | `crawl`, then `process` |
| `e20r crawl` | Crawl only (resumable); `--recrawl` starts over |
| `e20r process` | Process the crawled top-N repositories that need work |
| `e20r report` | Print the population summary, top packages and symbols, failures |
| `e20r view` | Serve the read-only viewer over the database (`--port`, `--host`) |
| `e20r export` | Write every table and view as JSONL (`--out`), for tools that do not read SQLite |

`process` (and `run`) decides per repository from its recorded state:
- nothing recorded yet → processed;
- `not-adopter` or `excluded` → done;
- `selected` → analyzed, unless `--skip-analysis`;
- `analyzed` → done, unless `--reanalyze` and an older analyzer version
  produced it;
- `failed` → retried while it has failed fewer than `--max-attempts` times.

Flags that change this:

| Flag | Effect |
| --- | --- |
| `-b, --repo-search-budget` | Number of top repositories to crawl and process |
| `-c, --concurrency` | Repositories processed in parallel |
| `--fresh` | Re-process every repository, whatever its state |
| `--reanalyze` | Re-process adopters recorded by an older analyzer version |
| `--retry-failed` | Retry failed repositories even past `--max-attempts` |
| `--max-attempts`, `--max-parse-bytes`, `--exclude-repos` | Override the `.env` settings below |
| `--skip-analysis` | Stop adopters at `selected` (no deep analysis) |
| `--cache-path` | Where `e20r.db` and the work directory live (default `.e20r`) |
| `--clean` | Wipe the database and the work directory first |
| `--no-cache` | In-memory database, temporary work directory: nothing survives |
| `--keep-clones` | Keep work directories after processing (debugging) |

## Configuration (`.env`)

| Key | Default | Meaning |
| --- | --- | --- |
| `GITHUB_API_KEY` | (none) | Required for crawling; also authenticates clones (see below) |
| `REPO_SEARCH_BUDGET` | `5000` | Top repositories to process (up to 30,000) |
| `CACHE_PATH` | `.e20r` | Database and work directory |
| `CONCURRENCY` | `4` | Repositories in parallel (1–16); choose from measured host headroom and whole-process-tree usage |
| `MAX_ATTEMPTS` | `3` | Attempts before a failing repository is given up on |
| `MAX_PARSE_BYTES` | `1000000` | Larger files are still read whole; imports scanned as text, with no symbol counts; not a memory limit |
| `EXCLUDE_REPOS` | (empty) | Comma-separated `owner/name` list kept out of the deep analysis |
| `EXCLUDE_EFFECT_COPIES` | `true` | Exclude repositories that define `effect` / `@effect/*` packages |
| `NO_CACHE` | `false` | Same as `--no-cache` |

These are **code defaults**, not the values selected by copying
`.env.example` (whose budget is `1200`). `src/config.ts` uses Effect's
`ConfigProvider.fromDotEnv()` with constant-case keys: it reads `.env` in
the process working directory, without merging `process.env` or expanding
variables. The file must exist and contain a recognized entry (an entirely
empty file currently fails decoding); absent settings use code defaults.
Command flags override the decoded settings, but an invalid `.env` can fail before
the overlay is applied. Exporting `CONCURRENCY=1` or `GITHUB_API_KEY` in the
shell does not configure this provider. For a defaults run, use a private
credential-only `.env`, an absolute cache path and explicit concurrency as
shown in the [operating guide](docs/operations.md#before-prepare-an-isolated-run).

**GitHub throttling.** GitHub rate-limits git traffic per IP, and anonymous
clones hit that limit after a few thousand (every clone then fails with
`could not read Username … terminal prompts disabled`). With
`GITHUB_API_KEY` set, clones and checkouts are authenticated, which raises
the limit a lot. The token travels as an HTTP header set through git's
environment config: never on the command line, never on disk, only to
`https://github.com/`. If clones still fail in a row, a circuit breaker
pauses new clones (2, 4, 8 … up to 30 minutes, reset by any success) and,
after five pauses without a success, stops the run, leaving the rest
pending. Failed repositories are retried by the next run.

## The data

`<cache>/e20r.db` (schema: `src/store/migrations.ts`). Each child table is
keyed by `repo_id` and replaced as a whole when its repository is
re-processed.

| Table | Grain |
| --- | --- |
| `repos` | Crawled repository: stars, forks, owner, license, topics, dates, raw payload |
| `repo_state` | Pipeline state: `status`, adopter, commit, exclusion reason, error and attempts, analyzer version, stage timings |
| `manifest_deps` | Every `effect` / `@effect/*` dependency: manifest × package × field × specifier |
| `catalog_versions` | pnpm / bun catalog entries for `effect` |
| `package_managers` | pnpm / bun / npm evidence from lockfiles |
| `workspace_packages` | Adopters' workspace packages (directory, name, how they declare `effect`) |
| `file_totals` | TS files, declaration files, LOC, Effect files and Effect LOC per package × role × extension (adopters), or per role × extension (everyone else) |
| `effect_files` | One row per file that imports Effect: package, role, LOC, bytes, parser, import and symbol counts |
| `file_imports` | Every Effect import: module, package, kind, line, bound names |
| `file_symbols` | Symbol usages per file: `symbol × kind` (call, property access, identifier, type reference) with a count |
| `runs` | One row per run: configuration, start and end, population summary |

The views `v_population`, `v_repo_adoption`, `v_symbol_usage` and
`v_package_usage` hold the usual aggregations. Any SQLite client works,
e.g. `sqlite3 .e20r/e20r.db`, DuckDB (`ATTACH '.e20r/e20r.db' (TYPE sqlite)`) or pandas.

Keep in mind that counts are syntactic: there is no type information, and a
local variable that shadows an import still counts. Test code accounts for
a large share of Effect usages, and generated code can dominate single
repositories, so pick the role you report on deliberately.

## Viewer

`e20r view` opens the database read-only, so it can stay open during a
run and refresh live. It has five views:
- **Overview**: the adoption funnel, adoption by popularity, how `effect`
  is declared, major versions, adoption depth, usage by file role, and the
  top packages and symbols;
- **Repositories**, with a drawer per repository linking every file and
  import to GitHub at the analyzed commit;
- **Symbols**;
- **Files**: every Effect file with its symbols, searchable by path and by
  symbol used, with a CSV export (one line per file × symbol);
- **Data**, the raw tables.

One filter row (repository, status, stars, code role, symbol position)
scopes all of them. See [`viewer/README.md`](viewer/README.md).

## Development

```sh
pnpm dev <command>        # run from source (tsx)
pnpm test                 # vitest: parser, inventory, store, analyzer, viewer queries
pnpm typecheck && pnpm lint && pnpm format:check
pnpm tsx scripts/test-process-repo.ts Effect-TS/effect pingdotgg/uploadthing
pnpm tsx scripts/audit-generated.ts <clone-dir>
```

- `scripts/test-process-repo.ts` runs the whole per-repository pipeline on
  named repositories against an in-memory database (needs network).
- `scripts/audit-generated.ts` lists what a checkout gets classified as
  generated, and why.

Code map:
- `src/github/`: search crawl and git plumbing;
- `src/analysis/`: selection probes;
- `src/deep-analysis/`: tree inventory, oxc usage collector, per-repository
  analysis;
- `src/pipeline/`: per-repository flow and orchestration;
- `src/store/`: SQLite schema and writes;
- `src/viewer/`: read-side queries and the HTTP server;
- `viewer/`: the static page.

Bump `ANALYZER_VERSION` (`src/deep-analysis/analyze.ts`) whenever the
analysis records something different, so `--reanalyze` can refresh
existing data. `.repos/` holds reference clones for coding agents and is
not analyzed (see `AGENTS.md`).
